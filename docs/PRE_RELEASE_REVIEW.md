# Pre-Release Review — v1.0.48-rc1

Thorough readiness review of the repository before public release. Categories:
Legal, Accuracy, Code, Tidiness. Each item is marked:

- 🔴 **Blocker** — must fix before release
- 🟡 **Should fix** — strongly recommended
- 🟢 **Nice to have**

## 1. Legal

### 1.1 Project license — OK
- `LICENSE` is present and is the canonical MPL-2.0 text.
- `README.md` documents "MPL-2.0, © 2026 OpenWatt srl" and links the file.

### 1.2 Attribution — OK
- README `## Credits` and `docs/HARDWARE.md` credit Re.alto (Elia) and
  link the plan-d-io P1-dongle upstream.

### 1.3 Third-party dependencies 🟡
`platformio.ini` `lib_deps`:

| Library | License |
|---------|---------|
| knolleary/PubSubClient | MIT |
| bblanchon/ArduinoJson | MIT |
| me-no-dev/ESPAsyncWebServer | LGPL-3.0 |
| me-no-dev/AsyncTCP | LGPL-3.0 |
| fastled/FastLED | MIT |

- **LGPL-3.0** (ESPAsyncWebServer, AsyncTCP) requires that recipients be able
  to modify and **relink** the LGPL'd components. The firmware is statically
  linked, so the standard way to comply is to make the relevant object files
  available (or offer them) on request. Add a short
  `THIRD_PARTY_NOTICES.md` documenting the dependencies and this obligation,
  and decide how you will satisfy relinking (e.g. publish `*.o` artifacts).
- MIT deps have no copyleft obligation beyond retaining their notices.

### 1.4 Secrets — none committed, but placeholders 🟡
No API keys, tokens, or private keys are present in tracked files. However the
repo ships **placeholder** values that must be injected at build time:

- `SALT_STRING "CHANGE_ME_SALT"` (`src/config.h:30`)
- `MQTT_BROKER_HOST "mqtt.example.com"` (`src/config.h:33`)
- `OTA_FIRMWARE_URL "https://api.example.com/..."` (`src/ota_client.cpp:8`)
- `fingerprint_default` / `salt_string` in `src/customers/*.json`
- `calculate_password.py` documents `password = MD5(deviceId + SALT)` — fine
  only while the SALT is a placeholder; if a real SALT were ever committed
  this would leak the AP-password scheme.

**Action:** confirm the production build injects real SALT/broker/OTA values
(out-of-band), and never commit them.

### 1.5 AP password scheme — dead code? 🟢
`wifi_manager.cpp` starts the AP **open** (`softAP(name, NULL)`), so the
`calculate_password.py` MD5 scheme appears unused. Either wire it in or remove
the script to avoid confusion.

## 2. Accuracy (docs vs. code)

### 2.1 README.md 🔴
- `## Configuration` shows `#define FIRMWARE_VERSION "v1.0.45"` — wrong
  macro (actual is `FIRMWARE_VERSION_BASE`) and wrong version (`v1.0.47`).
- `## Project Structure` shows a `firmwares/p1m5/` tree — the repo root *is*
  the project; there is no `firmwares/` directory.
- `## Reference Docs` points to `firmware/IMPLEMENTATION_SPEC.md`,
  `firmware/P1_PARSER_FINDINGS.md`, `firmware/README.md` — none of these exist.
- `## Full Documentation` links `DEVELOPMENT.md` — the actual file is `DEV.md`.
- `## Features` still says MQTT publishes to `mqtt.example.com` (placeholder).

### 2.2 DEV.md 🟡
- References `firmware/IMPLEMENTATION_SPEC.md` and `firmware/README.md`
  (non-existent).

### 2.3 CUSTOMERS.md 🔴
- `pio run -e m5stack-atom` — no such environment (real envs: `openwatt`,
  `soliseco`, `creos`, `test`).
- `extends = env:m5stack-atom` — same problem.
- "Firmware Version: OpenWatt `v1.0.24-ow`" — stale (now `v1.0.47`).
- Documents the `customer_config.py → customer_config.h` flow, which overlaps
  (and partly conflicts with) the `build_variant.py → variant_config.h` flow
  actually used by the `soliseco`/`creos` envs.

### 2.4 Config systems — consolidated 🟢 (resolved)
There were three parallel, partly conflicting ways of configuring variants:

1. `src/config.h` (hand-edited, compiled in),
2. `src/variant_config.h` (generated by `scripts/build_variant.py` from
   `firmware_variants.json`; committed as "do not edit"),
3. `src/customer_config.py` + `src/customers/*.json` → `src/customer_config.h`
   (gitignored).

`config.h` and `variant_config.h` both define `ENABLE_MQTT`, `ENABLE_OTA`,
`ENABLE_P1_READER`. Consolidate on one mechanism and document it.

**Resolved:** the `variant_config.h` / `firmware_variants.json` /
`build_variant.py` system was removed. `customer_config.py` +
`src/customers/*.json` (incl. a new `openwatt.json`) is now the single source,
auto-generated at build time for every environment.

## 3. Code

Covered in `docs/CODE_REVIEW.md`. Remaining open items that matter for a
public release:

- 🔴 No HTTP API authentication (open AP + open endpoints; arbitrary firmware
  flash via `/api/system/ota-pull`).
- 🔴 MQTT TLS validation disabled (`setInsecure()`).
- 🔴 OTA update is unsigned and not cert-validated.
- 🟡 Hardcoded `SALT_STRING` placeholder in `config.h`.
- 🟡 Fake/placeholder values published (`99.999` limiter, `999.99` fuse, `"0"`
  switch positions).
- 🟡 24-bit device ID (`P1` + 3 MAC bytes) — collision risk, also used as MQTT
  username.
- 🟡 MQTT config set via UI is overwritten by `begin()` on reboot.

The refactors (deduplication, `startSoftAP`, precedence fix) are merged.

## 4. Tidiness

- 🟡 `data/` (`index.html`, `settings.html`, `system.html`) duplicates
  `src/templates/*.html`; not referenced by the code (the firmware serves
  `src/generated/templates.h`). Remove or explain.
- 🟢 `include/README`, `lib/README` are PlatformIO boilerplate placeholders.
- 🟢 `src/generated/templates.h` is a committed generated file (fine — allows
  offline builds — but note it is regenerated by `build_templates.py`).
- 🟢 `diagram.json`, `wokwi.toml`, `scripts/wokwi_test.py` are Wokwi
  simulation tooling (harmless).
- 🟢 `.gitignore` only ignores `.pio` and `customer_config.h` — good; ensure no
  build artifacts are ever tracked.
